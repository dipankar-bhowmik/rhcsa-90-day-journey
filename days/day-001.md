# Day 1: Onboarding: build your two lab servers

## Break and fix
Not planned, but it happened: `ssh -T git@github.com` worked, then `git push` failed with "Could not resolve hostname github.com". `nslookup github.com` found the address but timed out on my resolver (172.25.96.1), so DNS was flaky, not the key. The push worked after I made the repo public and retried, so I will recheck DNS tomorrow.

## Runbook note
1. Install RHEL 10 in VirtualBox (2 CPU, 4 GB RAM, 20 GB disk).
2. Set the hostname with `hostnamectl set-hostname`.
3. Register with `subscription-manager`, then check `dnf repolist`.
4. Run the morning health check (df, free, uptime, systemctl --failed).
5. Take a snapshot named `day1-clean`.
Verify: hostname shows in `hostnamectl`, repos listed. Rollback: restore the snapshot.

## What I got wrong or learned
- I created the GitHub repo as private by mistake, then made it public.
- When a connection fails, test DNS first (`getent hosts github.com`, `nslookup`) before blaming keys.
- Do daily work as a normal user (test1), use sudo only when needed.
