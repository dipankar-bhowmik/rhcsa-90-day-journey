## Break and fix
Relative vs. Absolute Path Failure: Ran cd etc/sysconfig while inside /home/test1 and hit bash: cd: etc/sysconfig: No such file or directory because omitting the leading / makes the shell look for /home/test1/etc/sysconfig. Fixed by passing the absolute path cd /etc/sysconfig (or relative cd ../../etc/sysconfig).

Mystery File Without Extension: Copied /etc/hosts to /tmp/hosts with no extension to simulate an unlabeled file on a production server. Identified it immediately using file /tmp/hosts (ASCII text) and checked its inode/SELinux context with stat /tmp/hosts, then cleaned up /tmp/hosts.

## Runbook Note
Run df -hT and lsblk first on any unfamiliar server to see which directories (/, /boot, /home, /var) live on separate partitions or LVM volumes.

Check directory-level ownership and permissions with ls -ld <dir> rather than ls -l <dir>.

Use ls -lrt <dir> in /etc or /var/log to surface the most recently modified files at the bottom of the terminal.

Never trust file extensions on Linux; run file <path> to inspect the header and stat <path> to inspect inode number, link count, octal permissions, and SELinux context.

Rollback: All commands in this audit are read-only; no system state was altered.

## What I got wrong or learned
ls -l /usr lists the contents inside /usr, whereas ls -ld /usr shows the metadata of the /usr directory itself.

Top-level directories /bin, /sbin, /lib, and /lib64 are actually symbolic links (l) pointing to /usr/bin, /usr/sbin, /usr/lib, and /usr/lib64.

Both /tmp and /var/tmp survive reboots, but systemd cleans unaccessed files in /tmp after 10 days and in /var/tmp after 30 days.

Virtual filesystems (/proc, /sys, /dev, /run) live purely in memory and are recreated on every boot.

In /dev, ls -l replaces the byte-size column with major and minor device numbers (major = kernel driver ID, minor = specific device/partition instance).
